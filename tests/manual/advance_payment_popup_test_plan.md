# แผนทดสอบ Pop-up สำหรับ HTTP error ใน Advance Payment

สถานะ: แผนทดสอบ ยังไม่ได้รันเคสจริง

## ขอบเขตและวิธีทดสอบ

ทดสอบฟอร์มสัญญาเงินยืมในหน้า coordinator และ borrower โดยแยก **ช่วงตรวจข้อมูล** (`validation_only=1` ก่อนเปิดหน้าต่างยืนยัน) กับ **ช่วงบันทึกจริง** (คำขอหลังผู้ใช้กดยืนยัน) ข้อความด้านล่างเป็นข้อความที่ผู้ใช้ควรเห็น ไม่ใช่ HTTP code หรือรายละเอียดภายในระบบ

1. ใช้ระบบทดสอบ กรอกข้อมูลให้ถูกต้อง เปิด DevTools → Network แล้วตรวจ `POST`, HTTP status และ `Content-Type`
2. จำลอง response ด้วย Playwright `page.route()` หรือเครื่องมือดักคำขออื่น สำหรับ 500/502/503 ไม่ต้องทำให้เซิร์ฟเวอร์จริงล้ม
3. เมื่อต้องทดสอบช่วงตรวจข้อมูล ให้ดักคำขอที่มี `validation_only=1` แล้วคืน status/body ตามเคส
4. เมื่อต้องทดสอบช่วงบันทึกจริง ให้คำขอตรวจข้อมูลคืน `200 application/json` พร้อม `{"ok":true}` จากนั้นกดยืนยัน แล้วดักคำขอ `POST` ถัดไป
5. ตรวจหัวข้อ ข้อความ ปุ่ม “ตกลง” จำนวนคำขอ ข้อมูลในฟอร์ม และสถานะรายการหลังทดสอบ

**กฎสำคัญ:** 5xx ที่เกิดหลังการกดยืนยันบันทึก แสดง HTTP-16 เสมอ เพราะ HTTP response ไม่บอกว่าบันทึกฐานข้อมูลสำเร็จแล้วหรือยัง ส่วน HTTP-11 ถึง HTTP-15 ใช้กับช่วงตรวจข้อมูล (HTTP-14 ใช้เมื่ออ่าน JSON ในช่วงนั้นไม่ได้) ต้องตรวจรายการก่อนกดส่งซ้ำ

## 400 — คำขอหรือการยืนยันแบบฟอร์มไม่ผ่าน

| ID | เกิดขึ้นเมื่อไร / วิธีทดสอบ | หัวข้อ Pop-up | ข้อความที่แสดง |
| --- | --- | --- | --- |
| HTTP-01 | CSRF token ของฟอร์มหาย ไม่ตรง หรือใช้ไม่ได้แล้ว; Flask-WTF ปฏิเสธคำขอก่อนเข้า view และ handler คืน `400 application/json` พร้อม `title: "แบบฟอร์มหมดอายุ"` | แบบฟอร์มหมดอายุ | แบบฟอร์มนี้หมดอายุแล้ว กรุณาโหลดหน้าเว็บใหม่ แล้วลองส่งข้อมูลอีกครั้ง |
| HTTP-02 | ตัวกลางหรือ handler อื่นคืน `400 text/html` แทน JSON; จำลอง response เพื่อทดสอบ fallback | ไม่สามารถส่งข้อมูลได้ | ไม่สามารถส่งข้อมูลได้ในขณะนี้ กรุณาโหลดหน้าเว็บใหม่ แล้วลองอีกครั้ง |
| HTTP-03 | คืน `400 application/json` พร้อม `{"ok":false,"message":"ข้อมูลคำขอไม่ถูกต้อง"}` แต่ไม่มี `title`; ทดสอบข้อความทั่วไปเมื่อคำขอไม่ถูกต้อง | กรุณาตรวจสอบข้อมูล | ข้อมูลที่ส่งไม่ถูกต้อง กรุณาตรวจสอบข้อมูลแล้วลองอีกครั้ง |

## 401 และ 403 — การเข้าใช้งานหรือสิทธิ์

| ID | เกิดขึ้นเมื่อไร / วิธีทดสอบ | หัวข้อ Pop-up | ข้อความที่แสดง |
| --- | --- | --- | --- |
| HTTP-04 | จำลอง `401` หรือให้การเข้าสู่ระบบหมดอายุจน `fetch` ถูกพาไป `/auth/login`; เส้นทางปกติของ Flask-Login มักเป็น redirect มากกว่า 401 ตรง ๆ | กรุณาเข้าสู่ระบบใหม่ | การเข้าสู่ระบบหมดอายุแล้ว กรุณาเข้าสู่ระบบอีกครั้ง แล้วลองทำรายการใหม่ |
| HTTP-05 | ระบบงานที่เลือกเปลี่ยนในอีกแท็บ หรือไม่ตรงกับรายการที่เปิดอยู่; backend คืน `403 application/json` พร้อม `title: "ไม่สามารถทำรายการได้"` | ไม่สามารถทำรายการได้ | ระบบงานที่เลือกไม่ตรงกับรายการนี้ กรุณากลับไปเลือกระบบงานให้ถูกต้อง แล้วเปิดรายการนี้ใหม่อีกครั้ง |
| HTTP-06 | บัญชีไม่มีบทบาท/สิทธิ์ในระบบงาน หรือพยายามแก้สัญญาที่ตนไม่ใช่ผู้สร้างหรือผู้ยืม; backend คืน `403 application/json` พร้อมเหตุผลเฉพาะ | ไม่มีสิทธิ์ทำรายการ | เหตุผลจาก backend เช่น “บัญชีของคุณไม่มีสิทธิ์ดำเนินการรายการนี้ตามบทบาทที่ได้รับ” หรือ “คุณไม่ได้เป็นผู้สร้างหรือผู้ยืมของสัญญานี้” |
| HTTP-07 | จำลอง `403 text/html` หรือ JSON ที่ไม่มีเหตุผลเฉพาะ เพื่อทดสอบ fallback | ไม่มีสิทธิ์ทำรายการ | บัญชีของคุณไม่มีสิทธิ์ดำเนินการรายการนี้ กรุณาติดต่อผู้ดูแลระบบหากต้องการความช่วยเหลือ |

## 404, 422 และ 423 — รายการไม่พบหรือทำรายการไม่ได้

| ID | เกิดขึ้นเมื่อไร / วิธีทดสอบ | หัวข้อ Pop-up | ข้อความที่แสดง |
| --- | --- | --- | --- |
| HTTP-08 | ระหว่างแก้ไข `edit_ticket_id` ชี้ไปยังสัญญาที่ถูกลบหรือหาไม่พบ; backend `abort(404)` หรือจำลอง `404` | ไม่พบรายการที่ต้องการ | ไม่พบรายการที่คุณต้องการแก้ไข รายการอาจถูกลบหรือมีการเปลี่ยนแปลงแล้ว กรุณากลับไปตรวจสอบรายการอีกครั้ง |
| HTTP-09 | `form.validate()` ไม่ผ่าน บัญชีธนาคารที่เลือกถูกปิด หรือสัญญาเข้าสถานะที่แก้ไม่ได้; backend คืน `422 application/json` พร้อมสาเหตุเฉพาะ | กรุณาตรวจสอบข้อมูล | เหตุผลจาก backend เช่น “เลขที่บัญชีนี้ถูกปิดแล้วหรือไม่อยู่ในรายการที่เลือกได้” หรือ “สัญญาเงินยืมที่กำลังดำเนินการหรืออนุมัติเบิกจ่ายแล้วไม่สามารถแก้ไขข้อมูลได้” |
| HTTP-10 | อยู่ในช่วงปิดปีงบประมาณและ backend คืน `423` เมื่อเพิ่ม แก้ไข หรือส่งข้อมูล | ปิดรับการทำรายการชั่วคราว | ขณะนี้อยู่ในช่วงปิดปีงบประมาณ จึงไม่สามารถเพิ่ม แก้ไข หรือส่งข้อมูลได้ กรุณาลองใหม่เมื่อระบบเปิดให้บริการ |

## 500, 502 และ 503 — ปัญหาของระบบ

| ID | เกิดขึ้นเมื่อไร / วิธีทดสอบ | หัวข้อ Pop-up | ข้อความที่แสดง |
| --- | --- | --- | --- |
| HTTP-11 | **ช่วงตรวจข้อมูล:** backend มี exception ที่ไม่ได้จัดการ เช่น query ฐานข้อมูลล้ม และคืน `500 text/html` | ระบบขัดข้องชั่วคราว | ขออภัย ระบบไม่สามารถดำเนินการได้ในขณะนี้ กรุณาลองใหม่อีกครั้งภายหลัง หากยังพบปัญหา กรุณาติดต่อผู้ดูแลระบบ |
| HTTP-12 | **ช่วงตรวจข้อมูล:** จำลอง `500 application/json` พร้อม `message` ที่มี traceback หรือรายละเอียดฐานข้อมูล แต่ไม่มี `title`; ต้องไม่แสดงรายละเอียดภายใน | ระบบขัดข้องชั่วคราว | ขออภัย ระบบไม่สามารถดำเนินการได้ในขณะนี้ กรุณาลองใหม่อีกครั้งภายหลัง หากยังพบปัญหา กรุณาติดต่อผู้ดูแลระบบ |
| HTTP-13 | **ช่วงตรวจข้อมูล:** จำลอง `500 application/json` พร้อม `title` และ `message` เป็นรายละเอียดภายใน เช่น SQL error; ต้องซ่อนทั้งสองค่า | ระบบขัดข้องชั่วคราว | ขออภัย ระบบไม่สามารถดำเนินการได้ในขณะนี้ กรุณาลองใหม่อีกครั้งภายหลัง หากยังพบปัญหา กรุณาติดต่อผู้ดูแลระบบ |
| HTTP-14 | **ช่วงตรวจข้อมูล:** response ระบุ `application/json` แต่ body เป็น JSON ที่ parse ไม่ได้; จำลอง `500` พร้อม JSON เสีย | ระบบไม่สามารถแสดงผลได้ | ระบบไม่สามารถแสดงผลการตรวจสอบข้อมูลได้ในขณะนี้ กรุณาลองอีกครั้ง หากยังพบปัญหา กรุณาติดต่อผู้ดูแลระบบ |
| HTTP-15 | **ช่วงตรวจข้อมูล:** proxy หรือ upstream คืน `502`/`503` เพราะแอปไม่พร้อมให้บริการ | ระบบขัดข้องชั่วคราว | ขออภัย ระบบไม่สามารถให้บริการได้ในขณะนี้ กรุณาลองใหม่อีกครั้งภายหลัง หากยังพบปัญหา กรุณาติดต่อผู้ดูแลระบบ |
| HTTP-16 | **ช่วงบันทึกจริง:** หลังผู้ใช้กดยืนยันแล้ว server/proxy คืน 5xx ไม่ว่าจะเป็น HTML, JSON หรือ JSON เสีย; จำลองทั้งกรณีก่อนและหลัง `db.session.commit()` เพื่อยืนยันว่า UI ไม่สรุปว่าบันทึกล้มเหลว | ไม่สามารถยืนยันผลการบันทึกได้ | ระบบไม่สามารถยืนยันผลการบันทึกข้อมูลได้ กรุณาตรวจสอบรายการของคุณก่อนทำรายการซ้ำ เพื่อป้องกันการบันทึกข้อมูลซ้ำ หากไม่พบรายการ กรุณาติดต่อผู้ดูแลระบบ |

## บันทึกผล

บันทึก **ผ่าน/ไม่ผ่าน**, หน้า coordinator/borrower, ช่วงตรวจข้อมูล/บันทึกจริง, วิธีจำลอง, status, `Content-Type`, body, ภาพ Pop-up, จำนวน `POST` และสถานะข้อมูลก่อน–หลัง สำหรับ HTTP-12/13 ตรวจว่าไม่มี traceback, SQL หรือข้อความภายในหลุดขึ้นหน้าเว็บ สำหรับ HTTP-16 ตรวจรายการจริงก่อนส่งซ้ำ

## เส้นทางอื่นที่ใช้ข้อความชุดเดียวกัน

| เส้นทาง | กรณีที่ต้องจำลอง | ผลที่ต้องตรวจ |
| --- | --- | --- |
| ตั้งค่าผู้ดูแลบัญชีเงินยืม | `422` พร้อมเหตุผลเฉพาะ, `500` ทั้ง JSON/HTML, `200` ที่ขาดข้อมูลบัญชี | เหตุผล `422` แสดงตาม backend; อีกสองกรณีแสดง HTTP-16 และไม่ขึ้นข้อความ JSON parsing |
| บันทึกร่างรายการส่งคืน / เงินสดย่อย | GET ต่ออายุ CSRF คืน `401` หรือ redirect ไป login; POST autosave คืน `400` พร้อมเหตุผล, `500` JSON/HTML | GET แสดง HTTP-04; `400` แสดงเหตุผลจาก backend; `500` แสดง HTTP-16 ไม่แสดงรหัส HTTP ดิบ |
| Autosave พื้นหลัง | POST autosave คืน `500`, `401` หรือเครือข่ายขาดต่อเนื่องหลายครั้ง | แสดง Pop-up หนึ่งครั้งต่อช่วงที่ผิดพลาด และกลับมาแจ้งได้อีกหลัง autosave สำเร็จ; การกรอกบางส่วนที่ได้ `400` ไม่เปิด Pop-up ซ้ำทุกครั้ง |
| นำเข้าสัญญาเก่าในหน้า finance | `400` พร้อม `error` ว่าไฟล์ไม่ถูกต้อง, `500` พร้อมข้อความภายใน, `200` ที่ body ไม่สมบูรณ์ | `400` แสดงเหตุผลของไฟล์; `500` และ response ที่ยืนยันผลไม่ได้แสดง HTTP-16 ไม่แสดงรายละเอียดภายใน |
| ฟอร์มเปลี่ยนสถานะที่ใช้ `data-ajax-validation` | ส่ง POST แล้วได้ `500` หลัง server อาจเปลี่ยนสถานะแล้ว | แสดง HTTP-16 และให้ตรวจสถานะรายการก่อนส่งซ้ำ |
